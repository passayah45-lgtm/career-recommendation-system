# Machine-learning experiments

Run on 26 October 2026. Every number comes from `reports/ml_results.json`, which reproduces exactly with `python -m src.evaluation.ml_experiments --check reports/ml_results.json` (about 6 minutes). Model interpretation comes from `reports/ml_interpretation.json`.

**Status:** Completed experiment on synthetic, author-labelled data. Preliminary. Not evidence of real-world career-guidance quality.

## 1. Can the data support supervised learning?

Partly. The existing labelled profiles give a valid but small supervised task:

| Item | Value |
|---|---|
| Profiles | 36 synthetic, author-written (35 with at least one relevant career) |
| Candidate careers per profile | 50 |
| Learner-career pairs | 1,800 |
| Positive pairs (labelled relevant) | 56 (3.1%) |
| Label source | Author's binary labels, written with rules L1 to L5 and committed before the engine was run (commit d93b46b) |

What is missing for a trustworthy model:

- Labels from people other than the author.
- Real learner profiles in free text.
- Graded relevance (0, 1, 2).
- Many more positive examples: hundreds of profiles rather than 35.

The independent-label protocol in `experimental_protocol.md` (Part B) describes how to collect these after ethics approval.

**Risk of learning the labelling rules.** The labels were not generated by the scoring formula. They are, however, one person's judgement, and the features come from the same matching the formula uses. A model can therefore learn only the author's habits as expressed through these features. No result here measures whether careers suit real students.

## 2. Features (13 per pair)

Built by `src/ml/features.py` from the engine's own matching (`src/engine/matching.py`).

| Feature | Definition |
|---|---|
| required_coverage | matched required / required skills |
| required_matched | count of matched required skills |
| required_missing | count of missing required skills |
| required_total | number of required skills of the career |
| preferred_coverage | matched preferred / preferred skills |
| preferred_matched | count of matched preferred skills |
| interest_coverage | matched interests / career interests |
| interest_matched | count of matched interests |
| education_value | 1 minus 0.25 per level below the career level, floored at 0; 0 if no level |
| education_gap | levels below the career level; 0 if no level given |
| education_provided | 1 if the learner gave an education level |
| learner_skill_count | recognised learner skills |
| learner_skills_used_share | (matched required + matched preferred) / learner skills |

Excluded on purpose: career id, career category, profile id, profile category and profile type. These would let a model memorise label patterns instead of using the learner's information.

## 3. Models

| Model | Settings | Grid (inner CV) |
|---|---|---|
| Logistic Regression | StandardScaler in a pipeline, balanced class weights, max_iter 2000 | C: 0.01, 0.1, 1, 10 |
| Decision Tree | balanced class weights | max_depth: 2, 3, 4, 6; min_samples_leaf: 1, 5, 20 |
| Random Forest | 300 trees, balanced_subsample, n_jobs 1 | max_depth: 3, 6, None; min_samples_leaf: 1, 5 |
| XGBoost | subsample 0.9, colsample 0.9, hist, scale_pos_weight = negatives / positives in the training fold, n_jobs 1 | max_depth: 2, 3, 4; learning_rate: 0.05, 0.1; n_estimators: 100, 300 |
| Weighted formula | 0.55, 0.15, 0.25, 0.05; no training | none |

All models use random_state 42. Software used for the saved results: Python 3.13.16, scikit-learn 1.9.1, XGBoost 3.4.1, NumPy 2.5.4. GitHub Actions runs the test suite on Python 3.12.

## 4. Protocol

1. **Outer loop:** StratifiedGroupKFold with 5 folds. Groups are profiles and strata are the profiles' primary categories. All 50 pairs of a profile are always on the same side, which `tests/test_ml.py` checks.
2. **Inner loop:** GridSearchCV with GroupKFold (3 folds) on the outer training set, scoring by average precision. Scaling is fitted inside each fold only.
3. **Ranking:** test profiles' careers are sorted by predicted probability, with ties broken by career id.
4. **Classification threshold:** the threshold that maximises F1 on the outer training fold, for models and formula alike.
5. **Repeats:** 5 outer seeds (0 to 4). Each profile's metric is averaged over repeats, then macro-averaged over the 35 scorable profiles.
6. **Statistics:** 95% bootstrap intervals; a paired sign-flip randomisation test of each model against the formula (10,000 resamples); Holm correction across the four models.

## 7. Decision

- No trained model improves on the weighted formula, so none is integrated into the app. Production ranking stays with the formula, which keeps every score explainable.
- The trained models are available through `src/ml/ranker.py` (`TrainedRanker`). Its output has the same schema as `recommend()`, adds `model_probability`, and keeps the engine's explanations and skill gaps.
- One finding worth testing on new data: learner_skills_used_share, a signal the formula does not use.
- Before any model can win credibly, the project needs independent labels on real profiles (`experimental_protocol.md`, Part B).
